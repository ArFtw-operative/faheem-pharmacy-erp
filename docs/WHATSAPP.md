# WhatsApp invoices

Customers who ask for it receive their invoice PDF on WhatsApp from the pharmacy's own number.
It is **only** for customer-requested, transactional invoices: there is no bulk or promotional
sending. The optional image is attached to an invoice a customer asked for, never sent on its own.

```
POS / Sales History ──► queue (PostgreSQL) ──► worker ──► WPPConnect gateway (stack-internal) ──► pharmacy's WhatsApp
```

## 1. Turn the gateway on (once, on the pharmacy PC)

The gateway is part of the appliance stack (service `whatsapp`, image `wppconnect/wppconnect-server`
pinned to a version). It has **no published port**: only the ERP's worker reaches it, on the stack's
private network. Its secret is generated by the installer into `/etc/faheem-erp/faheem.env`.

- Desktop: **ERP Control Center → Settings → WhatsApp invoices**, or
- `sudo faheem-erp whatsapp enable`   (`disable` stops it; the linked phone stays paired)
- `sudo faheem-erp whatsapp-status`

The linked session is kept in `/var/lib/faheem-erp/whatsapp/`, so restarts and updates do not ask for
a new QR code. While the gateway is stopped, invoices queue and are retried.

## 2. Pair the pharmacy's WhatsApp (Administrator)

Settings → **WhatsApp Invoicing** → **Connect WhatsApp**, then scan the QR code with the pharmacy
phone (WhatsApp → Linked devices → Link a device). The status reads **Connected**.

- **After a reboot:** the session reconnects by itself (no new QR) while the phone keeps the link.
- **Reconnect:** starts the session again.
- **Log out WhatsApp:** unlinks the phone. A new QR is then needed.

Only users with `settings.manage` (Administrators) see the Settings tab, the QR or these buttons.
The gateway URL and secret are never shown in the app.

## 3. Message and image (Administrator)

- **Invoice message:** used as the caption of the PDF.
  - Placeholders: `{pharmacy}` `{invoice_no}` `{customer}` `{amount}` `{date}`.
  - Default: “Thank you for shopping at {pharmacy}. Please find your invoice #{invoice_no} attached.”
- **Image sent with invoices:** PNG / JPEG / WebP up to 2 MB, with an optional caption. It's sent
  after the PDF only when the tick is on. Replace it any time: earlier images are kept on disk.
  If the image fails, the invoice still counts as sent.
- **Test:** sends the latest bill's invoice to a number you type.

## 4. Sending

- **POS**, after Complete sale:
  - **P Print invoice**;
  - **W WhatsApp invoice** goes to the customer's saved mobile; for walk-ins, or with no saved
    number, you type the number the customer gives;
  - **N No invoice**.
  - WhatsApp is queued and the next bill starts at once; the status bar reports "sent" or the
    reason it failed.
- **Sales History:** **WhatsApp** / **Resend WhatsApp** (F9), with the bill's delivery log and
  **Retry** for failed ones.
  - A resend delivers the **same stored invoice PDF**. It never creates a sale or invoice.
  - An edited bill (same number, new lines) gets a new PDF.
  - Voided bills can't be sent.
- **Numbers** are normalised to `91XXXXXXXXXX`. Accepted forms: `98765 43210`, `+91 98765 43210`,
  `098765 43210`, `919876543210`.

## 5. Delivery and failures

Each send is a row in `whatsapp_messages`:
- `sale_id` (the invoice)
- `customer_phone`
- `status` (queued / sending / sent / failed)
- `attempt_count`
- `last_error`
- `sent_at`
- `is_resend`
- `pdf_path`

A background worker delivers the queue. The queue lives in the database, so it survives restarts.

| Problem | What happens |
|---|---|
| Gateway down / network / WhatsApp disconnected | Retried after 30 s and 2 min, then **failed** with the reason. Retry from Sales History |
| Number not on WhatsApp | Failed at once (retrying cannot help) |
| WhatsApp disconnected | POS and Sales show “WhatsApp disconnected — reconnect from Settings.” Billing is never blocked |

## 6. Security

- **Gateway address:** reachable on 127.0.0.1 only. The app refuses a `PHARMACY_WPP_URL` that is
  not a loopback or private-network address.
- **Secrets:** the secret key is only in environment files (mode 600), never in code or the
  database. The bearer token is derived on demand and kept in memory.
- **Session data:** session files live inside the gateway's Docker volumes, never in the app's
  uploads or snapshots.
- **Audit:** every send, retry, pairing, logout and setting change is in the audit log.

> WPPConnect drives WhatsApp Web; it is not an official WhatsApp product. Keep sending to
> customer-requested invoices. The provider sits behind `app/services/whatsapp/provider.py`, so
> the official WhatsApp Business (Cloud) API can replace it without changes to POS or Sales.
